### 2026-11-12, commit 6 spike notes (written before code): Teamwork Graph
Sources: Forge "Call the Teamwork Graph API", Teamwork Graph "Persisted cypher queries", "Scopes", object-type pages, a community post on silent failures.
- Call from a Forge backend: `api.asUser().requestTeamworkGraph(query, { queryKey, queryParams })`, GraphQL field `customQuery(queryKey, queryParams, first: 25)`; results at `data.customQuery.edges[].node.columns[]` (`key`, `value`; a node value has `id` = ARI). Calls run as the user only; there is no asApp. Raw `cypherQuery` is not available to new apps. Page size max 25. The Forge page calls the API Preview; the API reference overview calls it EAP (conflict, unresolved).
- GraphQL operation names must look like `[company]_[operation]` (company >= 3 chars, operation >= 4); a bad name is HTTP 200 with `errors` (`DataFetchingException`). Execution errors also come as HTTP 200 with `data.customQuery` null and `errors[].extensions.code` (for example `QUERY_NOT_FOUND`, which can appear for about a minute after registration).
- Registration of a saved query: `POST https://<site>.atlassian.net/gateway/api/twg/cypher-queries` with `{appId, name, cypher, paramsSchema?}` returns `{queryKey, version, contentHash, status}` (201; same text again 200 with the same key). The caller must be a contributor on the app. The doc does NOT say how to authenticate (errors `UNIDENTIFIED_CALLER` 401, `NOT_CONTRIBUTOR` 403). I did not find a CLI command for it. So registration needs the owner (see "Owner must register" below); this session cannot do it and no key exists yet.
- Relations (object-type pages): `content_entity_links_entity`: JiraWorkItem -> ConfluencePage (confirmed). `jira_work_item_shared_with_atlassian_user`: JiraWorkItem -> AtlassianUser (confirmed). `atlassian_user_mentioned_in_jira_work_item`: NOT listed on the JiraWorkItem page; name and direction (assumed user -> work item) unconfirmed; registration validates names, so a wrong one is rejected there.
- Scopes (Teamwork Graph scopes page): `read:graph:issue:jira`, `read:graph:page:confluence`, `read:graph:user:atlassian`. `read:graph:jira` and `read:graph:confluence` are retired. A missing scope is NOT an error: rows are silently omitted, so an empty result is ambiguous. Hence the UI says "Teamwork Graph returned nothing" and never "no linked pages".
